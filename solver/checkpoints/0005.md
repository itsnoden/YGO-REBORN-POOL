## Double Spell stack-overflow diagnosis

The earlier held-out evaluator consistently failed at:
- candidate: `593df70fb35282f5`
- seed: `21101`
- learned seat: `1`
- process call: `2105`

The diagnostic stack trace showed repeated recursion through:
- `c24096228.lua` — **Double Spell**
- `c96947648.lua` — **Salvage**

The pre-fix state had player 0 holding Double Spell while player 1's GY
contained both Double Spell and Salvage. During activation-legality probing,
`Double Spell` called `CheckActivateEffect` on a GY Double Spell. That GY copy's
target check re-entered the same legality path repeatedly until Lua/ocgcore
reported `C stack overflow`.

This was not a learner error. It reproduced deterministically in the pinned
engine/script environment.

### Fix

Added reviewed solver-side override:
`script_overrides/c24096228.lua`

The override preserves the pinned/current Double Spell cost, target and operation
logic but adds a recursion guard **only while a Double Spell target's own
activation legality is being checked**. It does not globally ban Double Spell as
a Double Spell target: a GY Double Spell can still be considered when there is a
real non-cyclic downstream Spell that makes the copied effect usable.

`reborn/ocgcore.py` now resolves scripts in this order:
1. reviewed `solver/script_overrides/<filename>`
2. pinned CardScripts root
3. pinned CardScripts `official/`

Only explicitly present reviewed overrides take precedence. Added tests verify
Double Spell override presence, override precedence, and ordinary fallback to
the pinned official script.

The current Project Ignis master script was checked and still contained the same
recursive `CheckActivateEffect` implementation, so simply advancing CardScripts
would not remove this blocker.

The public alphabetically numbered pool file and solver MASTER numbering are
**different index systems**. The temporary apparent candidate/name mismatch was
resolved: search candidates use the canonical solver MASTER/video-order IDs.
`reborn-0529` in that MASTER is Double Spell. No engine mapping error was inferred
from the public-share numbering.
